# 系统架构设计

> 更新时间：2026-08-05（初版）

## 1. 总体架构

系统采用**四层架构**：前端交互层 → 业务后端层 → 多智能体服务层 → 数据引擎层。

```
┌────────────────────────────────────────────────────────────┐
│  前端交互层  frontend/（Vue 3 + Vite + TS + Element Plus）   │
│  · Vue Flow 思维链可视化（Agent 思考过程动态展示）           │
│  · SSE 流式推送（实时接收 Agent 状态）                      │
│  · 人在回路介入按钮（假设生成后暂停，人类修改后继续）        │
└──────────────────────────┬─────────────────────────────────┘
                           │ HTTP / SSE
┌──────────────────────────▼─────────────────────────────────┐
│  业务后端层  backend/（Spring Boot 3.x + Java 17）          │
│  · RESTful API（任务提交、历史查询、报告获取）              │
│  · SSE 流式转发（将 AI 服务流转发给前端）                   │
│  · MySQL 持久化（用户、任务、报告）                         │
└──────────────────────────┬─────────────────────────────────┘
                           │ 内部 HTTP（REST + SSE）
┌──────────────────────────▼─────────────────────────────────┐
│  多智能体服务层  ai-service/（Spring Boot + LangChain4j）    │
│  · 七 Agent DAG 管线（State 状态流转）                      │
│  · @Tool / @AiService 定义                                  │
│  · 百炼平台 Qwen 模型调用封装                               │
│  · 四库 RAG 检索接口                                        │
└──────────────────────────┬─────────────────────────────────┘
                           │ JDBC / Java SDK
┌──────────────────────────▼─────────────────────────────────┐
│  数据引擎层  data/（Python + 向量数据库 + MySQL）            │
│  · 论文库 / 方法库 / 数据集库 / 证据库                      │
│  · Milvus（生产）/ Chroma（开发）                           │
│  · 混合检索：向量相似度 + BM25                              │
└────────────────────────────────────────────────────────────┘
```

## 2. 通信链路

### 2.1 主流程（前端 → 后端 → AI 服务）

```
用户提问
  → 前端 POST /api/tasks（提交科研问题 + 参数）
  → 业务后端创建任务记录，转发至 ai-service POST /pipeline/run
  → ai-service 执行七 Agent 管线，实时推送 Agent 状态事件（SSE）
  → 业务后端转发 SSE 事件流给前端
  → 前端 Vue Flow 动态渲染思维链；在「人在回路暂停点」等待人类介入
  → 人类审阅/修改后继续 → 管线继续执行
  → 完成 → 生成《科学假设与研究计划》→ 前端展示 + 后端持久化
```

### 2.2 SSE 事件模型

AI 服务通过 SSE 推送以下事件类型（字段细节由后端组设计时确定）：

| 事件 | 含义 |
|---|---|
| `agent.start` | 某 Agent 开始执行 |
| `agent.thinking` | Agent 思考过程（token 流） |
| `agent.result` | 某 Agent 产出阶段性结果 |
| `pipeline.pause` | 到达人在回路暂停点（等待人类介入） |
| `pipeline.resume` | 人类确认继续 |
| `pipeline.done` | 管线完成，输出最终报告 |
| `pipeline.error` | 管线异常 |

## 3. 服务划分与部署

| 服务 | 工程 | 端口 | 职责 |
|---|---|---|---|
| 前端 | `frontend/` | 5173（dev） | 交互界面、可视化 |
| 业务后端 | `backend/` | 8080 | API、SSE 转发、持久化 |
| 多智能体服务 | `ai-service/` | 8081 | Agent 管线、LLM 调用、RAG 检索 |
| MySQL | docker-compose | 3306 | 关系数据 |
| Chroma / Milvus | docker-compose | 8000 / 19530 | 向量数据 |

> 部署形态：开发期本地多进程；生产期 Docker 容器化（`docker-compose.yml` 已编排中间件，应用镜像由各小组补充）。

## 4. 关键技术决策

| 决策点 | 结论 | 理由 |
|---|---|---|
| 前后端分离 | 是 | 分工明确，SSE 适合长连接流式场景 |
| 业务后端与 AI 服务 | **两个独立工程** | 职责解耦：业务侧专注 API/持久化，AI 侧专注管线；可独立部署、独立扩容 |
| SSE 链路 | 前端只连业务后端，业务后端转发 AI 服务流 | 统一出口、便于鉴权与日志记录 |
| 人在回路实现 | 管线 State 中设置暂停点，等待外部确认事件 | 满足赛题「可交互、具备教学意义」要求 |
| 向量数据库 | 开发用 Chroma，生产切 Milvus | 配置化切换（`VECTOR_DB` 环境变量） |

## 5. 扩展与容错（由团队细化）

- Agent 级超时与重试
- LLM 调用限流与成本控制（Qwen-Max 重任务 / Qwen-Plus 轻任务分级）
- 任务断点恢复（State 持久化）
- API 调用日志与百炼凭证截图留存（赛题强制要求）
