# 通用知识发现 Agent 设计

## 目标

在不依赖具体科研领域的前提下，将用户问题和可溯源论文证据转换为结构化研究空白，并输出下游假设生成 Agent 可直接消费的待研究问题、论文标题和论文摘要。

本次只实现马艺萌可以独立完成的内容：知识发现的数据契约、三阶段分析服务、提示词和自动测试。向量数据库接入、论文下载解析、百炼底层客户端、DAG 编排以及其他 Agent 不在本次范围内。

## 输入与输出

输入包含：原始科研问题、可选领域标签、论文证据列表。每条论文证据至少包含标题、摘要或片段、作者、年份，以及 DOI、PMID、URL 中至少一种可追溯标识。

输出包含：

- 已知发现、研究局限和跨论文冲突；
- 按价值排序的 Research Gap，每项附证据标识、置信度和排序理由；
- 选定的 Problem Statement、Paper Title、Paper Abstract；
- 本次分析实际使用的参考文献标识。

输出采用 Java 类型承载，并能稳定序列化为 JSON。缺失必要输入或模型返回无效 JSON 时，服务返回清晰错误，不悄悄生成无来源结论。

## 处理流程

`KnowledgeDiscoveryService` 负责单一入口，并按三个阶段调用现有 `BailianClient`：

1. 证据提取：逐篇归纳研究问题、方法、结论、局限和未来工作。
2. 跨论文比较：识别共同局限、结论冲突、未覆盖场景和技术迁移机会。
3. 空白排序：按新颖性、证据强度、可行性和问题清晰度排序，生成最终选题字段。

服务通过现有 `RagSearchService` 获取论文证据；同时允许调用方直接传入证据，便于独立测试和在队友尚未完成向量库时联调。领域信息只作为输入，不在代码或提示词中写死“SSD”。

## 边界与协作

- 不修改 `PipelineEngine`，仅提供清晰的服务入口供张睿接入。
- 不实现 Chroma/Milvus、Embedding 或论文抓取；这些继续由现有 RAG 和数据接口负责。
- 不实现假设生成 Agent；输出契约保持结构化，供黄晴昀直接调用。
- 不增加新的第三方依赖，优先使用 Spring Boot 已带的 Jackson 和现有客户端。

## 测试与验收

自动测试使用模拟 RAG 与模型响应，不需要 API Key 或向量数据库，覆盖：

- 三阶段调用顺序及最终结构化输出；
- 通用领域输入不会被替换为固定 SSD 主题；
- 空证据、缺失来源标识及无效模型 JSON 会明确失败；
- 输出引用只能来自输入论文证据。

验收以 `ai-service` 测试通过、代码可编译、文档说明接入方式为准。功能分支为 `feature/mayimeng-knowledge-discovery`，提交后推送并以 `develop` 为合并目标。
